# Товары > 3D-модель товара

### ℹ️ Что это такое

К товару можно прикрепить 3D-модель из DayZ. Покупатель сможет покрутить предмет прямо в карточке товара: вращать мышкой (или пальцем на телефоне) и приближать колёсиком.

Вы загружаете обычный архив с моделью и текстурами, а магазин сам:

* рисует **картинку-превью** модели — она показывается в каталоге, если у товара нет своих изображений;

---

### 📦 Что положить в архив

Архив — **только `.zip`** (rar и 7z не принимаются). Максимальный размер — **12 МБ**. Структура папок внутри не важна: файлы ищутся по имени.

| Файл | Обязателен | Описание |
|---|---|---|
| `*.p3d` | ✅ Да | Модель в **небинаризованном** виде (MLOD). Если в архиве несколько p3d — берётся самый большой |
| `*_co.paa` | Желательно | Цветная текстура (цвет предмета). Подойдут также `*_ca.paa` (с прозрачностью) или `.png` / `.jpg` |
| `*_nohq.paa` | Нет | Карта нормалей — добавляет рельеф (швы, складки ткани). Без неё модель выглядит более «плоской» |
| `*.rvmat` | Нет | Материал. Из него магазин узнаёт, какая карта нормалей относится к модели |
| `model.cfg` | Нет | Можно положить, но для показа он не нужен (там скелет и анимации) |

Остальные файлы (`_smdi`, `_as`, `config.cpp` и т.д.) можно оставить в архиве — они просто игнорируются.

**Пример архива:**

```
Backpack.zip
└── Backpack/
    ├── alicebackpack_m_mlod.p3d      ← модель (MLOD)
    ├── alicebackpack_black_co.paa    ← цвет
    ├── alicebackpack_nohq.paa        ← рельеф
    ├── alice_backpack.rvmat
    └── model.cfg
```

---

### ⚠️ Важно: модель должна быть MLOD, а не ODOL

В DayZ есть два вида `.p3d`:

* **MLOD** — исходная, редактируемая модель. Её открывает **Object Builder** из DayZ Tools. **Нужна именно она.**
* **ODOL** — «бинаризованная» модель, которая лежит внутри `.pbo` готовых модов и самой игры. Её магазин **не принимает**.

Если вы распаковали `.pbo` и взяли оттуда `.p3d` — почти наверняка это ODOL, и магазин покажет ошибку *«Модель бинаризована (ODOL)»*. Возьмите исходник модели у автора мода или экспортируйте модель из Object Builder (**File → Save As**, без бинаризации).

::: tip Как проверить
Откройте `.p3d` в любом текстовом редакторе: первые 4 символа файла — `MLOD` (подходит) или `ODOL` (не подходит).
:::

### 🎨 Как магазин находит текстуры

Внутри модели прописаны игровые пути к текстурам, например `dz\characters\backpacks\data\alicebackpack_co.paa`. Магазин ищет файл в архиве так:

1. Файл с **точно таким же именем** (`alicebackpack_co.paa`, также `.png` / `.jpg`).
2. Если такого нет — **самый похожий по имени файл с тем же окончанием** `_co` / `_ca`. Поэтому перекрашенные варианты работают сами: модель ссылается на `alicebackpack_co.paa`, а в архиве лежит `alicebackpack_black_co.paa` — будет взят он.
3. Если текстура не найдена — модель покажется серой.

Для одного товара — один вариант расцветки. Если у предмета несколько расцветок (чёрный, зелёный, камуфляж), положите в архив **только нужную** `_co`-текстуру, иначе магазин выберет одну из них сам.

Поддерживаются текстуры в форматах **DXT1** и **DXT5** — в них обычно хранятся `_co`, `_ca` и `_nohq` текстуры DayZ (так их сохраняют ImageToPAA и TexView 2 из DayZ Tools).

### ⚙️ Загрузка в админке

1. **Управление → Товары**, открываем нужный товар.
2. Вкладка **«Основные настройки»**, поле **«3D-модель (zip)»** — под полем «Изображения».
3. Перетаскиваем архив и нажимаем **«Сохранить»**.
4. Модель конвертируется в фоне (обычно несколько секунд). Обновите страницу — под полем появится статус:

| Статус | Что значит |
|---|---|
| **Модель конвертируется…** | Обработка ещё идёт, обновите страницу через минуту |
| **Модель сконвертирована и показывается в карточке товара** | Готово ✅ |
| **Ошибка конвертации: …** | Что-то не так с архивом — причина написана в тексте, см. таблицу ниже |

* **Заменить модель** — загрузите новый архив вместо старого и сохраните.
* **Убрать модель** — удалите файл из поля и сохраните. 3D-просмотр и превью пропадут вместе с ним.

---

### 👀 Что увидит покупатель

| Где | Товар с изображениями | Товар без изображений |
|---|---|---|
| **Каталог** | Ваше первое изображение | Картинка-превью модели на фирменном фоне |
| **Окно товара** | Изображения, последняя миниатюра — **«3D»** | Сразу открывается 3D-просмотр |

3D-модель загружается **только когда покупатель открывает её** в окне товара — каталог от этого не тяжелеет.

::: warning
Файл 3D-модели, который получает браузер, можно скачать. Водяные знаки стоят на фоне просмотра и превью, а не на самой модели. Не загружайте модели, которые вы не готовы показывать публично.
:::

### 🛠 Частые ошибки

| Текст ошибки | Что делать |
|---|---|
| Модель бинаризована (ODOL) | Нужна исходная модель (MLOD), см. раздел выше |
| В архиве нет p3d-модели | В архиве нет файла `.p3d` — проверьте, что упаковали нужную папку |
| Не удалось открыть zip-архив | Архив повреждён или это не zip (например, rar с расширением .zip). Перепакуйте в zip |
| Неподдерживаемый формат PAA | Текстура сохранена не в DXT1/DXT5. Пересохраните её через ImageToPAA или TexView 2 |
| Файл не является p3d-моделью (MLOD) / p3d-файл обрезан | Файл модели повреждён — экспортируйте модель заново |
| В модели нет визуального LOD с полигонами | В модели только служебные LOD (геометрия, тени). Нужен файл с видимой моделью |
| Архив слишком большой после распаковки | Уберите лишнее: другие расцветки, `_smdi`, `_as`, исходники |
| Модель серая | Не найдена `_co`-текстура — положите её в архив (см. «Как магазин находит текстуры») |
| Загрузка висит на 100% | Уберите из архива лишние текстуры и попробуйте снова. Если архив меньше 12 МБ и всё равно висит — напишите в поддержку |
